Set up your workspace app

The workspace app is the window you work in every day. Pick one, install it, and connect it to the model you downloaded.

5Choose your workspace app

The workspace app is the window you work in every day, and it replaces the Claude or ChatGPT website. All of these are free and all of them can use the model you just downloaded. Pick one to start. You can add another later, since they all share the same Ollama models.

Start here

Open WebUI

The closest thing to a Claude project. A chat window in your browser with model presets, a system prompt per preset, and knowledge bases you upload files to.

Needs: Docker. Best for: most people.

Free

LibreChat

A ChatGPT-style chat window that can switch between your local model and any paid service you keep, in one place.

Needs: Docker and Git. Best for: people mixing local and cloud models.

Free

Hermes Agent

An open-source agent from Nous Research that does tasks rather than just chatting. It runs in the terminal and can also connect to apps like Telegram or Discord.

Needs: no Docker, but a larger model. Best for: replacing a coding or task agent.

Prefer a regular desktop app over a browser window? LM Studio and AnythingLLM are free desktop apps that skip Docker. This guide covers the three above because they give you a full project workspace, but those two are good options if Docker gives you trouble.

Check: you have picked one app. If you are not sure, pick Open WebUI.

6Install Docker (for Open WebUI or LibreChat)

Docker runs the workspace app in a sealed box, so it installs the same way on every computer and does not touch the rest of your system. Skip this step if you chose Hermes Agent only. Docker Desktop is free for personal use and small businesses. Check Docker's pricing page if you use it for a larger company.

Mac

Download Docker Desktop for Mac, choosing the Apple Silicon or Intel version to match your chip. Drag it into Applications, open it, and wait until it says Docker is running.

Windows

Download Docker Desktop for Windows and run the installer. Keep the WSL 2 option selected when it asks. Restart if prompted, then open Docker Desktop and wait until it says Docker is running.

Linux

Install Docker Engine using the instructions for your distribution, which include the Compose plugin that LibreChat needs.

docker --version

Check: the command prints a version, and Docker Desktop (on Mac and Windows) shows it is running. Ollama must also still be running.

7Install the workspace and connect it to your model

Follow the part for the app you picked. In each case the app finds your model by talking to Ollama at port 11434 on your own computer. From inside Docker that address is host.docker.internal:11434, and from outside Docker it is localhost:11434.

Option A: Open WebUI

Run this one command in your terminal. It downloads Open WebUI, starts it, and points it at Ollama on your computer. This is the method Open WebUI's own docs recommend.

docker run -d -p 3000:8080 --add-host=host.docker.internal:host-gateway -v open-webui:/app/backend/data --name open-webui --restart always ghcr.io/open-webui/open-webui:main
  1. Wait a minute or two, then open http://localhost:3000 in your browser.
  2. Create an account. It lives only on your computer, not online. The first account you create is the admin.
  3. Start a new chat and choose your model from the menu at the top.

If the model menu is empty, open Admin Panel, then Settings, then Connections, and set the Ollama address to http://host.docker.internal:11434.

Linux: Ollama only listens to your own machine by default, so the container may not reach it. The simplest fix is to run Open WebUI on the host network instead, then open http://localhost:8080:

docker run -d --network=host -v open-webui:/app/backend/data -e OLLAMA_BASE_URL=http://127.0.0.1:11434 --name open-webui --restart always ghcr.io/open-webui/open-webui:main

Check: you can chat with your model in the browser.

Option B: LibreChat

LibreChat installs from its code repository, so you also need Git. Run these in your terminal, one at a time. On Windows, use copy .env.example .env for the third line.

git clone https://github.com/LibreChat-AI/LibreChat.git
cd LibreChat
cp .env.example .env
cp docker-compose.override.yml.example docker-compose.override.yml

Now tell LibreChat about Ollama. Create a file named librechat.yaml in the LibreChat folder with this in it. The API key can be any word, because Ollama ignores it.

version: 1.2.1
endpoints:
  custom:
    - name: "Ollama"
      apiKey: "ollama"
      baseURL: "http://host.docker.internal:11434/v1/"
      models:
        default: ["qwen3:8b"]
        fetch: true
      titleConvo: true
      titleModel: "current_model"

Open docker-compose.override.yml and make sure the lines that mount librechat.yaml are not commented out (remove the # in front of them). Then start it:

docker compose up -d
  1. The first start takes a few minutes. Then open http://localhost:3080.
  2. Click Sign up and create your account. The first account is the admin.
  3. Pick Ollama from the endpoint menu, then your model.

Edited the YAML file later? Restart with docker compose down and then docker compose up -d.

Check: Ollama appears in the endpoint menu and your model answers.

Option C: Hermes Agent

Hermes needs a bigger model and a bigger working memory (its "context") than plain chat, because an agent reads tool results as it works. Its docs suggest gemma4:31b, which needs around 24 GB of memory or more. Install it with the command for your system:

Mac

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.zshrc

Windows (PowerShell)

iex (irm https://hermes-agent.nousresearch.com/install.ps1)

Close and reopen PowerShell afterwards.

Linux

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.bashrc

Then give your model a bigger context. Ollama's default context is small, and Hermes' docs say agent work needs at least 64,000 tokens. Make a plain text file named Modelfile with these two lines:

FROM gemma4:31b
PARAMETER num_ctx 64000

In the same folder, build a copy of the model with that setting:

ollama create gemma4-64k -f Modelfile

Now connect Hermes to it. Run hermes setup, choose Custom Endpoint, and enter:

  • Base URL: http://localhost:11434/v1
  • API key: leave it empty
  • Model: gemma4-64k

Then start it with hermes.

Check: Hermes answers using your local model. A bigger context uses more memory, so if it becomes very slow, lower num_ctx or use a smaller model.
